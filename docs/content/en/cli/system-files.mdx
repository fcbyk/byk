# System Files

`@@@` is the third file domain. `@` points at the current directory, `@@` at the
global alias directory, and `@@@` at **system files inside the CLI home
(`~/.byk/`)** — files that belong to byk itself, not to any project.

```bash
byk @@@file command [args...]
```

Two exist today:

| Form | Target |
|------|--------|
| `@@@config` | `~/.byk/config.json` |
| `@@@tap` | `~/.byk/tap/`, with `index.json` as its ledger |

- System files never take part in alias lookup, and have no `clone` / `link`:
  there is no notion of several of them referencing each other.
- The name after `@@@` must be a registered system file; a typo reports
  `Unknown system file` and lists the available names.
- Commands follow the name after a space, not a dot: `@@@config.set` reports
  `Invalid system file`.

## config

### Commands

With no command it prints every setting (the common case); `-h` prints usage
help instead.

| Command | What it does |
|---------|--------------|
| `list` | Print every setting (same as no command) |
| `get <key>` | Print one value, safe for `$(...)` |
| `set <key> <value>` | Validate, then write |
| `unset <key>` | Remove the key, falling back to its default |

```bash
byk @@@config                    # every setting
byk @@@config get banner         # auto
byk @@@config set banner never   # drop the box above `-h`
byk @@@config unset banner       # back to the default
```

`get` prints a bare value; `set` / `unset` report on stderr, so pipelines stay
clean.

### Settings

| Key | Values | Default | Purpose |
|-----|--------|---------|---------|
| `banner` | `auto` / `always` / `never` | `auto` | The decorative box above `-h` |

`auto` hides it when stdout is not a terminal, so `byk -h | head`, scripts, and
editor plugins get clean output for free. `always` and `never` are literal.

When scanning alias files turns up problems, the `N alias files have problems`
line **ignores this setting**: it is a warning, not decoration.

### The file

```json
{ "banner": "auto" }
```

- A missing file is normal — every key falls back to its default, no error.
- Unreadable content (broken JSON, a non-object top level) prints one warning
  and falls back to defaults with the usual exit code; a broken config must not
  take `-h` down with it.
- Writes are atomic and keep every key they read, including keys this version
  does not know yet.
- Keys are written back in alphabetical order, so a hand-written order gets
  normalized.
- The `Config:` line of `byk --paths` is this file.

## tap (`@@@tap`)

`@@@tap` does one thing: put a tap repository into
`~/.byk/tap/<user>/<repo>`, so you stop typing `git clone` by hand.

```bash
byk @@@tap                      # what is installed (same as list)
byk @@@tap add aaa/bb           # download and record, ref defaults to HEAD
byk @@@tap add aaa/bb@v1        # pin a ref
byk @@@tap remove aaa/bb        # unrecord and delete
```

| Command | What it does |
|---------|--------------|
| `list` | Show the repositories in the ledger (same as no command) |
| `add <user>/<repo>[@<ref>]` | Download, validate, move into place, then record |
| `remove <user>/<repo>` | Unrecord, then delete the directory |

`<user>` and `<repo>` accept letters, digits, `.`, `-`, and `_` only: they are
both directory names and URL segments.

### Directory and index

The ledger is `~/.byk/tap/index.json`, and only `@@@tap` reads or writes it:

```json
{
  "aaa/bb": { "origin": "github", "ref": "HEAD" }
}
```

- The key is `<user>/<repo>`; the directory follows from it, so no absolute
  paths are stored — moving machines or your home directory cannot make the
  ledger lie.
- `origin` is `github` today; `ref` is the ref used at install time.
- **Losing the ledger does not affect `clone --tap`**: it scans directories and
  never reads this file. You lose a list, not the feature.
- Entries that cannot be read are still listed (`origin` / `ref` show `?`),
  otherwise you could neither see nor remove them.
- Writes are atomic, sharing the same path as `config.json`.

### Rules of behaviour

- `add` **never overwrites** an existing directory; `remove` first to change
  versions.
- The repository root must contain a parsable `byk.tap.json`, or the install
  rolls back immediately and leaves nothing behind — once a local index exists
  it is authoritative, and a broken one would keep every key of that repository
  failing.
- Downloads use `curl`, extraction uses the system `tar`; the archive and the
  unpack directory are deleted afterwards.
- `remove` only knows the keys in the ledger. A repository you `git clone`d in
  by hand is not in it, so `remove` reports `not installed` and will not delete
  it.
- What you get is a snapshot with no `.git`, so it never updates itself; follow
  a new version or switch refs with `remove` + `add`.
- Downloads and the index write both follow the usual proxy settings such as
  `BYK_PROXY`.
