# 特殊文件

三个作用域都有名字：`work@` 是当前目录（不向上查找），`global@` 是 CLI 别名目录，`special@` 收纳的是各自带专属命令的非别名文件——`config`、`tap` 与 `shell`。只有作用域可以缩写成唯一前缀——`w@` / `wo@` / `wor@`、`g@`、`s@`。

`work@` 与 `global@` 找的是别名文件，`special@` 与它们相反：指向**不是别名文件**的那些，每一项都有自己的专属命令。它们既不是别名文件，也不是操作系统层面的「系统文件」：`config` 是 CLI Home（`~/.byk/`）里属于 byk 自己的配置，`tap` 是 `~/.byk/tap/` 下的 tap 仓库，`shell` 是用户自己的 shell 启动文件。

```bash
byk special@文件 命令 [参数...]
```

目前有三个特殊文件：

| 写法 | 目标 |
|------|------|
| `special@config` | `~/.byk/config.json` |
| `special@tap` | `~/.byk/tap/`，账本是其中的 `index.json` |
| `special@shell` | 当前 shell 的启动文件，如 `~/.zshrc` |

- 特殊文件不参与别名查找，也没有 `clone` / `link`：它们不存在“多份互链”的概念。
- `special@` 后面的名字必须是注册过的特殊文件，拼错会报 `Unknown special file` 并列出可用项。
- 动词与名字之间用空格，不是点号：`special@config.set` 会报 `Invalid special file`。
- `config` 与 `tap` 的目标是 byk 自己的文件，坏了最多回退默认值；`shell` 的目标是**别人的文件**，所以它只增删一段标记块，绝不整体重写。

## config

### 命令

不带命令时打印全部设置（这也是最常用的一屏），`-h` 才是用法帮助。

| 命令 | 作用 |
|------|------|
| `list` | 列出全部设置项（等于不带命令） |
| `get <键>` | 打印一个值，可直接进 `$(...)` |
| `set <键> <值>` | 校验后写入 |
| `unset <键>` | 删除该键，回到默认值 |

```bash
byk special@config                    # 看全部设置
byk special@config get banner         # auto
byk special@config set banner never   # 关掉帮助页顶部的装饰框
byk special@config unset banner       # 回到默认
byk special@config set net-github ghproxy  # 之后 GitHub 文件都经 gh-proxy 取
```

`get` 打印裸值；`set` / `unset` 的状态提示写 stderr，管道里不会混进输出。

### 设置项

| 键 | 取值 | 默认 | 作用 |
|----|------|------|------|
| `banner` | `auto` / `always` / `never` | `auto` | `-h` 顶部的装饰框 |
| `net-github` | `direct` / `ghproxy` | `direct` | 访问 GitHub 文件时走的通道 |

`auto` 在 stdout 不是终端时不显示——`byk -h | head`、脚本与编辑器插件拿到的帮助天然干净。`always` 与 `never` 是字面意思。

扫描别名文件时发现问题，那句 `N alias files have problems` **不受这个设置影响**：它是诊断，不是装饰。

`net-github` 只影响**读写 GitHub 文件的请求**：`clone` 的来源、`--tap` 的远程索引与目标、`$deps` 里指向 GitHub 的资产。它不改写 URL 里写的地址，也不进 `$deps.base`——落盘的永远是规范上游地址，镜像只在请求那一刻套用，所以同一份文件换台机器不用改。

两条边界：带凭证的地址（`?token=…`、`user:pass@host`）一律直连，镜像看不到它们；`special@tap add` 走的是 `git clone`，镜像帮不上忙，那条路只有代理管得着（见 `BYK_PROXY`）。

### 文件

```json
{ "banner": "auto" }
```

- 文件不存在是正常状态，全部键用默认值，不报错。
- 内容读不懂（坏 JSON、顶层不是对象）时只打一行警告并全部回退到默认值，退出码照常——配置坏了不该连 `-h` 都打不开。
- 写入是原子的，并且保留读到的全部键，包括当前版本还不认识的键。
- 键按字母顺序写回，手写的顺序会被规范化。
- `byk --paths` 的 `Config:` 一行就是这个文件的位置。

## tap（`special@tap`）

`special@tap` 干两件事：把 tap 仓库装进 `~/.byk/tap/<user>/<repo>`，以及把它们拉到上游最新——都不用再手敲 `git clone` / `git pull`。它只走 git，所以 `add` 与 `update` 需要系统里有 git。

```bash
byk special@tap                      # 看已装的仓库（等于 list）
byk special@tap add aaa/bb           # 默认从 GitHub 装，ref 默认 HEAD
byk special@tap add aaa/bb@v1        # 固定 ref
byk special@tap add my/tools https://git.example.com/my/tools.git   # 任意 git 地址
byk special@tap update               # 把账本里的每一份都拉到上游最新
byk special@tap update aaa/bb        # 只更新这一份
byk special@tap remove aaa/bb        # 注销并删除目录
```

| 命令 | 作用 |
|------|------|
| `list` | 列出账本里的仓库（等于不带命令） |
| `add <user>/<repo>[@<ref>] [<git-url>]` | 克隆、校验、落盘，再登记 |
| `update [<user>/<repo>]` | `fetch` 上游再 `reset --hard`，不带参数就是全部 |
| `remove <user>/<repo>` | 注销并删除目录 |

`<user>` / `<repo>` 只能是字母、数字、`.`、`-`、`_`，因为它们同时是目录名。

### 自定义来源

第二个参数会**原样交给 `git clone`**：`https://`、`ssh://`、`git@host:path`、`file://`、本地路径都行——不设协议白名单，反正 git 自己会拒绝 `ext::` 那类会把 URL 变成命令的形态。

```bash
byk special@tap add my/tools                         # https://github.com/my/tools.git
byk special@tap add my/tools git@git.example.com:tools/tap.git
byk special@tap add local/scratch ~/src/tap          # 本地仓库，装完 origin 记 local
```

- **`<user>/<repo>` 只是本地名字**：目录位置和账本的键都用它，不承诺与地址对应，也不校验（和 `brew tap user/repo URL` 一致）。
- 唯一的要求是「不像一个选项」：不能以 `-` 开头、不能含空白，否则会被 git 当成参数而不是地址。
- 没写地址时默认 `https://github.com/<user>/<repo>.git`。
- 私有仓库靠你自己的 ssh key / credential helper；byk 关掉了交互式提问，认证不通过会立刻报错而不是挂着等密码。

### 更新（update）

本质就是把你当初 `git clone` 下来的那份跟上游对齐——byk 用的是 `git fetch` + `git reset --hard`，不是 `git pull`：

- tap 是只读镜像，没有本地提交要合并，所以不需要 merge/rebase 语义；
- 上游 force push 过的分支、被移动过的 tag 也能跟上（`fetch --force`）；
- 浅克隆保持浅克隆，不会被悄悄补成一整份历史。

```bash
byk special@tap update               # 账本里的每一份都更新
byk special@tap update aaa/bb        # 只更新一份
# Updated aaa/bb (1a2b3c4 → 5d6e7f8)
# ccc/dd is already up to date
```

- **更新跟着账本里的 `ref` 走**：`update aaa/bb` 不会因为命令行没写 `@v1` 就跑回默认分支。钉在 tag 上时，上游不动 tag 就没有东西可更。
- **更新不写账本**：装了什么、钉在哪个 ref 都没变，变的只有 checkout 里的提交。`byk special@tap list` 里那份清单，更新前后一模一样。
- **本地改过的 checkout 不动**：`reset --hard` 会把这些改动一起抹掉，所以先报 `has local changes` 让你自己决定（提交、挪走，或者 `remove` + `add`）。
- **索引没了就回滚**：上游要是把 `byk.tap.json` 删了，这次更新退回到原来的提交，不让 checkout 停在 `--tap` 用不了的状态。
- 不带参数时**一份失败不拦下其余**：逐条报完，最后用一条 `Failed to update 1 of 2 tap repositories: …` 收尾，退出码 1。
- 只认账本：`update` 不会碰你自己 `git clone` 进来的目录，目录被删了会报 `Tap repository is missing`。

### 目录与索引

账本是 `~/.byk/tap/index.json`，只有 `special@tap` 读写它：

```json
{
  "aaa/bb": { "origin": "github", "ref": "HEAD" },
  "my/tools": {
    "origin": "git.example.com",
    "ref": "HEAD",
    "url": "ssh://git@git.example.com/my/tools.git"
  },
  "local/scratch": { "origin": "local", "ref": "HEAD", "url": "/Users/coke/src/tap" }
}
```

- 键是 `<user>/<repo>`，目录位置由键推导，所以索引里不存绝对路径——换机器、挪家目录都不会让账本变成谎话。
- `origin` 是来源的 host（`github.com` 写成 `github`，没有 host 的本地来源写 `local`）；`ref` 是安装时用的 ref，也是之后 `update` 跟随的目标。
- `url` 只在给了第二个参数时出现：默认源的地址能推导出来，存了是重复。
- **账本丢了不影响 `clone --tap`**：它扫的是目录，不读这个文件。少一份清单，功能照旧。
- 读不懂的条目照样会列出来（`origin` / `ref` 显示 `?`），否则用户既看不见也删不掉它。
- 写入是原子的，与 `config.json` 同一套。

### 行为约定

- `add` **不覆盖**已存在的目录，要换版本就先 `remove`。
- 目标仓库根必须有可解析的 `byk.tap.json`，否则落盘后立刻回滚，不留下半个目录——本地索引一旦存在就是权威，装一个坏索引会让该仓库所有 key 的 `--tap` 一直失败。
- `add` 只走 `git clone --depth 1`，装进来的是真仓库，之后可以自己 `git -C ~/.byk/tap/<user>/<repo> pull`。没有 curl + tar 的兜底：两条路的产物不一样，语义要解释两遍，故障面也多一倍。
- **`add` / `update` 需要 git**（Homebrew 的 tap 也是这样，它不内置 git）。`list` / `remove` 不需要——它们只读账本、删目录，没装 git 也能用。没有 git 又一定要装，就手工把仓库放到 `~/.byk/tap/<user>/<repo>`。
- `remove` 只认账本里的键。手工 `git clone` 进去的仓库不在账本里，`remove` 会报 `not installed`，因此也删不掉它。
- 浅克隆没有历史，但 `pull` 可用，`update` 也是在它上面继续做浅更新；换 ref 一律 `remove` + `add`。
- 下载跟随 `BYK_PROXY` 等代理设置，翻译成 git 的 `-c http.proxy`；索引写入不联网。
- 装第三方 tap 等于信任它给的别名文件：`add` 本身只搬运数据，真正的风险发生在之后 `clone --tap` 取用并执行那些别名时。

## shell（`special@shell`）

管理 shell 补全：在你当前 shell 的启动文件里加一段带标记的块，或者把它摘掉。

```bash
byk special@shell                    # 等同 -h：当前 shell、会改哪个文件、补全装没装，连同用法一屏
byk special@shell add completion     # 给当前 shell 装补全
byk special@shell remove completion  # 摘掉
```

| 命令 | 作用 |
|------|------|
| `add completion` | 写入补全块；已经装过就只报一句 |
| `remove completion` | 摘掉补全块，文件其余内容一个字节都不动 |

不带参数与 `-h` 是同一屏，输出逐字节相同：这一域只有两条动词，单开一屏「状态」等于让人多敲一次才能知道能做什么。`special@config -h` / `special@tap -h` 头顶那几行也是这个排法。

对象名可以只写前缀，`byk special@shell add comp` 与 `byk special@shell add completion` 等价——只认唯一命中，将来加了第二个对象、两个都能接上时报歧义，不会替你挑一个。

目标 shell 就是运行 byk 的那个，不接受指名，见下面「没有 switch，也不能指名」。

### 目标文件怎么定

不看操作系统，看环境。macOS 默认 zsh，但 `/bin/bash` 一直在；Windows 上的 Git Bash 同理——按 OS 猜会猜错，按 shell 认就不会。PowerShell 的 `$PROFILE` 落点本身随操作系统不同，那是 PowerShell 自己的规矩，不算按 OS 猜 shell。

| shell | 启动文件 |
|-------|----------|
| zsh | `$ZDOTDIR/.zshrc`，没设就是 `~/.zshrc` |
| bash | `.bash_profile` → `.bash_login` → `.profile` → `.bashrc` 里第一个存在的；都没有就创建 `.bash_profile` |
| fish | `$XDG_CONFIG_HOME/fish/config.fish`，没设就是 `~/.config/fish/config.fish` |
| pwsh | `$PROFILE`：mac / Linux 是 `$XDG_CONFIG_HOME/powershell/Microsoft.PowerShell_profile.ps1`（没设就是 `~/.config/powershell/…`），Windows 是「文档」下的 `PowerShell\Microsoft.PowerShell_profile.ps1` |
| powershell | Windows PowerShell 5.1 的 `$PROFILE`：「文档」下的 `WindowsPowerShell\Microsoft.PowerShell_profile.ps1` |

bash 那一行不是随手排的：登录 shell 只读前三者，`.bashrc` 只被非登录交互 shell 读，所以它排在最后——前面都不存在、它存在，才说明你走的是那条路。一个都不存在时新建 `.bash_profile` 是安全的，因为没有可被它屏蔽的文件；反过来，`.profile` 存在却去建 `.bash_profile`，会把你原来那份整份屏蔽掉。

当前 shell 的判定顺序是**父进程名 → `$SHELL`**。`$SHELL` 是登录 shell，`exec bash` 之后它仍然写着 zsh，所以父进程优先；Unix 从 `/proc`（或 `ps`）取父进程名，Windows 走 Toolhelp 快照，`powershell.exe` / `pwsh.exe` / `bash.exe` 一样能认出来。取不到（受限环境、编辑器直接拉起 byk）才退回环境变量。`special@shell` 把判定结果和它的来源一起打出来：

```bash
$ byk special@shell

Shell: zsh (from parent process)
FilePath: /Users/coke/.zshrc
Completion: installed (lines 3-5)

Usage: byk special@shell [OPTIONS] [COMMAND] [ITEM]

Options:
  --help, -h  Show this help

Commands:
  add     Enable shell completion
  remove  Disable shell completion

Items:
  completion  Shell completion
```

前三行同一级：标签同为绿色，冒号后一个空格就是内容——不为了对齐去补空白，路径长短差得远，补出来的空格比信息还多。空一行之后是用法，所以「现在指向谁」和「能做什么」在同一个屏幕里，不用先敲一次状态再敲一次 `-h`。

`.zshrc` 是 dotfiles 仓库的符号链接时，会多一行 `Target:` 指出真正被写的文件——写的时候也是写到它上面，链接本身不会被换成普通文件。

### 没有 switch，也不能指名

目标由环境决定，所以既没有「切换配置文件」的子命令，也不接受在命令行里指名——写了会被拒绝，并告诉你该去哪儿跑：

```bash
$ byk special@shell add completion bash
`add` takes no shell argument: it always updates the startup file of the shell running byk
Hint: run `byk special@shell add completion` from bash to set up bash
```

理由是这类错配**不会报错**：在 zsh 里把补全写进 `.bash_profile`，眼前这个终端毫无反应，也没有任何提示告诉你装错了地方。要装 bash 的补全就进 bash 再跑一次——「我改的是哪个文件」因此永远只有一个答案，它和 `special@shell` 打出来的那一行、和你眼前那个终端必然一致。

### 其他 shell：cmd、sh

补全生成器覆盖 `zsh`、`bash`、`fish` 和 PowerShell（`pwsh` / Windows PowerShell 5.1）。在别的 shell 里跑 `special@shell` 不算出错——它照实回答「当前 shell 没有指向任何文件」：

```bash
$ byk special@shell

Shell: sh (from $SHELL)
FilePath: (none)
Completion: not available
Only zsh, bash, fish and PowerShell have a startup file byk can edit
```

这一屏到这儿就完了，不接 `Usage` / `Commands`：没有文件可改，`add` 与 `remove` 在这台机器上都做不成，列一份用不上的清单只是噪声。显式敲 `-h` 也一样——两个入口是同一份输出。原因那行紧贴字段、不另起一段，因为它是 `Completion: not available` 的解释；整屏上下各留一个空行，和 zsh 那屏一样。

退出码是 0：这是一句正常的回答，不是失败。真去改（`add` / `remove`）才失败，退出码 1，文案就是上面那两句——因为它们确实什么都没做：

```bash
$ byk special@shell add completion
No startup file for sh (from $SHELL)
Only zsh, bash, fish and PowerShell have a startup file byk can edit
```

父进程与 `$SHELL` 都给不出答案时（Windows 的 cmd 常见），`Shell:` 一行显示 `unknown`，提示换成 `Only zsh, bash, fish and PowerShell are supported; run byk from one of them`。要用补全，就在这四个里面跑 byk。

### 写入纪律

这是 `special@` 里唯一改**别人**文件的对象，所以规矩和 `config.json` 不一样：

- 只增删标记块（`# The following lines have been added by byk to enable byk cli completions.` 到 `# End of byk cli completions`），文件其余字节原样保留，包括手写的顺序与 CRLF 行尾；标记写成完整句子而不是 `# >>> ... >>>`，因为这份文件是给人读的；
- 符号链接写到目标，链接仍在；
- 认 `install.sh` 早期版本写的无标记裸行：`remove` 删得掉（`uninstall.sh` 也认），`add` 只提示“已装”并建议摘了重装；
- 幂等：重复 `add` 不会多出一份；没有补全时 `remove` 什么都不做，退出码 0。

安装脚本不再自动写这一行（与 pip 一样，只负责把二进制放好）。装完自己开一次：

```bash
byk special@shell add completion
```

## 补全

特殊文件的语法归各自定，所以候选也向文件本身要，不套文件命令那张动词表：

- 敲 `special@` 列出 `config`、`tap` 与 `shell`，各带一句说明；
- 敲完 `special@config` / `special@tap` / `special@shell` 补动词；`-` 开头补 `--help` / `-h`——它只在动词位，`special@config set -h` 里的 `-h` 是 `set` 的参数；
- `get` / `set` / `unset` 补设置名，`set <设置名>` 补齐该键的候选值（如 `banner` → `auto` / `always` / `never`）；
- `remove` / `update` 补账本里的 `<user>/<repo>`；`add` 的来源在远端，不补；
- `add` / `remove` 的第一位补 `completion`，之后什么都不补——目标 shell 由运行环境决定，补一个 `bash` 出来就是教用户去做一件会被拒绝的事。

不带参数的动词（`list`、没写名字的 `get`）后面没有候选，shell 不会替你插词。
