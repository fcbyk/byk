# 别名配置

## 类型定义

```ts title="alias.types.ts"
// 别名对象（带元数据的形式）
type AliasObject = {
  $cmd?: string;
  $cwd?: string;
  $mode?: 'normal' | 'interactive' | 'silent';
  $description?: string;
  [key: string]: string | AliasObject | boolean | undefined;
}

// 一个 *.byk.json 文件：别名对象，或单导入数组
type AliasFileJSON =
  | {
      $priority?: number;      // 优先级，默认当前目录 = 1、全局 = 0
      $cwd?: string;           // 文件级 / 分组级工作目录，子别名自动继承
      $mode?: 'normal' | 'interactive' | 'silent';  // 文件级 / 分组级执行方式，子别名自动继承
      $paths?: string[];       // 文件级 PATH 目录列表，子别名自动继承
      $var?: Record<string, string | Record<string, string>>;  // 文件级变量
      [key: string]: string | AliasObject | number | boolean | undefined;
    }
  | [string];  // 单导入：只含一个路径的数组
```

文件里只认这五个 `$` 开头的键，其余 `$xxx` 一律原样透传给 shell（或由 [变量](#变量) 展开）。

## 别名对象

### Key 命名规则

- key **不能包含** `@` 或 `.`，违规则该条目被静默忽略
- 支持中文 key 名
- 支持嵌套分组（object），通过 `.` 分隔符访问

### 系统字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `$cmd` | string | 执行命令 |
| `$cwd` | string | 工作目录（可继承） |
| `$mode` | `'normal'` \| `'interactive'` \| `'silent'` | 执行方式（可继承），默认 `normal` |
| `$description` | string | 帮助页描述文本（不可继承） |

:::note
含 `$cmd` 的 object 是别名叶子节点。只有 `$cwd` / `$mode` 而没有 `$cmd` 的 object 是**带继承属性的分组**，本身不可执行。
:::

### 工作目录 cwd

三级继承：文件级 → 分组级 → 别名级，越靠近别名优先级越高。支持 `~`；**相对路径以别名文件所在目录为基准**解析，与你在哪个目录敲 `byk` 无关。不写 `$cwd` 时用调用时的工作目录。

<Tabs>
<Tab label="别名级指定">

```json
{
  "install": {
    "$cmd": "npm i",
    "$cwd": "/project/web"
  }
}
```

</Tab>
<Tab label="分组级继承">

```json
{
  "services": {
    "$cwd": "/project",
    "install": "npm i",
    "web": {
      "$cwd": "/project/web",
      "dev": "pnpm dev",
      "build": "pnpm build"
    }
  }
}
```

`install` 继承 `services` 的 `/project`，`web.dev` 与 `web.build` 使用 `web` 分组覆盖的 `/project/web`。

</Tab>
<Tab label="文件级继承">

```json
{
  "$cwd": "/project/web",
  "install": "npm i",
  "start": {
    "$cmd": "pnpm dev",
    "$cwd": "/project/web/frontend"
  }
}
```

`install` 继承文件级的 `/project/web`，`start` 使用自己的 `/project/web/frontend`。

</Tab>
</Tabs>

### 执行方式

`$mode` 决定别名怎么跑，三态互斥，默认 `normal`。

| 值 | 行为 |
|---|---|
| `normal` | 打印提示行，然后直接执行 |
| `interactive` | 打印提示行，逐项询问占位符，回车确认后才执行 |
| `silent` | 连终端上也不打提示（管道场景本来就不打） |

执行前 byk 会往 **stderr** 打两行提示：来源（`文件.key` 与落地目录）和解析后的最终命令。
走 stderr 而不是 stdout，是因为这两行是给人看的旁白，不该混进可以被管道消费的数据：

- `byk build > log.txt`、`byk build | grep error` 拿到的只有命令自己的输出；
- stderr 不是终端时（被 `2>` 重定向、CI、编辑器任务）这两行干脆不打；
- 想连终端上也保持安静，才写 `$mode: "silent"`。

```bash
byk build
# > @.build /project
#
# > pnpm build
#
# ...（pnpm 的输出）

# "$mode": "silent" 时
byk build
# ...（只剩 pnpm 的输出）
```

`interactive` 适合有副作用的命令：

```bash
byk deploy
# ~ deploy --env {env} --tag {version}
#   env: staging
#   version: v2.0
# ~ deploy --env staging --tag v2.0     ← 绿色粗体
#    Press Enter to execute...
```

`$mode` 支持三级继承：文件级 → 分组级 → 别名级，越靠近别名优先级越高。

<Tabs>
<Tab label="别名级指定">

```json
{
  "deploy": {
    "$cmd": "deploy --env {env} --tag {version}",
    "$mode": "interactive"
  }
}
```

</Tab>
<Tab label="分组级继承">

```json
{
  "danger": {
    "$mode": "interactive",
    "drop": "rm -rf {path}",
    "backup": {
      "$cmd": "rsync -a ./ {dest}",
      "$mode": "silent"
    }
  }
}
```

`drop` 继承 `danger` 的 `interactive`；`backup` 写一个 `silent` 就够，不需要再把交互关一次。

</Tab>
<Tab label="文件级继承">

```json
{
  "$mode": "silent",
  "build": "pnpm build",
  "deploy": {
    "$cmd": "deploy --env {env}",
    "$mode": "interactive"
  }
}
```

整个文件安静，只有 `deploy` 需要确认。

</Tab>
</Tabs>

:::note
交互和静默是互斥的两种形态：交互必须让用户看清要确认什么，所以 `silent` 只是让 byk 闭嘴，
不会跳过任何确认步骤——需要确认就写 `interactive`。
:::

### 描述文本

`$description` 替代帮助页里默认显示的命令文本，仅对当前别名生效、不继承。

```json
{
  "更新版本号": {
    "$mode": "interactive",
    "$cmd": "cz bump {version}",
    "$description": "交互式更新版本号"
  }
}
```

```text title="byk -h 片段"
Aliases:
  发布.更新版本号    交互式更新版本号
```

未设置时显示命令本身：

```text
Aliases:
  发布.更新版本号    cz bump {version}
```

### PATH 目录

`$paths` 在执行别名前把目录前置到 `PATH`，让别名可以直接调用这些目录下的可执行文件。

**仅支持文件级**，所有子别名自动继承；写在分组里会被忽略。

```json title="run.byk.json"
{
  "$paths": ["./scripts", "~/tools/bin"],
  "deploy": "deploy.sh",
  "check": "lint.sh"
}
```

- 相对路径以配置文件所在目录为基准解析，`~` 会展开
- **不存在的目录静默跳过**，不会出现在子进程的 `PATH` 里
- 另外，别名运行时 byk 会自动把工作目录下的 `node_modules/.bin` 追加到 `PATH` 前面——不需要也不应该自己写进 `$paths`
- `$paths` 的顺序就是 `PATH` 里的优先级顺序，越靠前越优先

### 变量

变量来自两处，合并成**一张表**，扫描期一次性替换完成。内置变量只有目录这一类，名字一律以 `_dir` 结尾、值都是绝对路径：

| 来源 | 说明 |
|------|------|
| 内置 | `${byk_dir}` → `~/.byk`（资源根，不是二进制目录）；`${file_dir}` → 当前别名文件所在目录 |
| `$var` 声明 | 文件级自定义变量 |

同名时**文件声明覆盖内置**——显式写下的值，就是你预期的那个值。

语法统一为 `${name}`，`name` 为 `[A-Za-z_][A-Za-z0-9_]*`（与 shell 标识符一致）：

```json title="run.byk.json"
{
  "$var": {
    "BASE": "https://github.com/owner/repo/releases/download",
    "VER": {
      "darwin-arm64": "tool-mac",
      "linux-x86_64": "tool-linux"
    }
  },
  "fetch": "curl -fsSL ${BASE}/${VER} -o /tmp/tool",
  "log": "tail -f ${byk_dir}/logs/app.log"
}
```

| 规则 | 说明 |
|------|------|
| 语法 | `${name}`，花括号是定界符，必须写 |
| 裸 `$xx` | 不识别，原样交给 shell（`$HOME`、`$PATH` 照常由 shell 展开） |
| 作用域 | 文件级，替换 `$cmd` / `$cwd` / `$paths` 等所有字符串值；JSON key 不动 |
| 覆盖 | `$var` 与内置同名时取 `$var` 的值 |
| 自引用 | `"byk_dir": "${byk_dir}/tools"` 等号右边取内置原值，结果为 `~/.byk/tools` |
| 转义 | `\${byk_dir}` 原样交给 shell，最终打印字面量 `${byk_dir}` |
| 平台映射 | 值可为平台映射（`linux-x86_64` / `linux-arm64` / `darwin-x86_64` / `darwin-arm64` / `windows-x64`），取当前平台的值 |
| 交叉引用 | 变量值之间可互相引用，与书写顺序无关，最多展开 8 轮 |
| 未定义 | `${XXX}` 原样保留；`args` 是参数占位符保留名，声明会被忽略 |
| 非法名 | 不符合标识符规则的名字被忽略，并在 stderr 提示 |

:::tip 为什么必须写花括号
裸 `$byk_dir` 没有结束符，`$byk_dirfoo` 到底是变量 `byk_dirfoo` 还是 `byk_dir` 接上 `foo`，无法判断。`${byk_dir}foo` 没有这个歧义——这也是它和 shell 写法一致的原因。
:::

**引号自己负责**：值里含空格时按 shell 规则自己包引号，byk 不会替你加。

```json title="run.byk.json"
{
  "log": "tail -f \"${byk_dir}/my logs/app.log\"",
  "where": "echo ${file_dir}"
}
```

`${file_dir}` 是**别名文件所在目录**：既不是 `$cwd` 指定的落地目录，也不是调用 `byk` 时所在的目录。需要后者时直接用 shell 的 `$PWD`。

## 别名文件

byk 读取两个位置：**全局目录** `~/.byk/alias/` 与**当前工作目录**（不递归）。

### 文件命名规范

| 格式 | 示例 | 说明 |
|------|------|------|
| `[name].byk.json` | `run.byk.json` | 推荐形式，名字即文件 key |
| `.byk.json` | `.byk.json` | 匿名形式，key 为空串 |

:::warning
**合法字符**：字母、数字、`-`、`_`、中文。

**禁止字符**：`.`、`@`、`/`、空格。

非法命名的文件（如 `aaa.bbb.byk.json`）会被**静默跳过**，不报错。
:::

### 目录结构

```tree
# 全局
~/.byk/alias/
├── alias.byk.json
├── work.byk.json
└── .byk.json
```

```tree
# 当前目录
./
├── run.byk.json
├── release.byk.json
└── .byk.json
```

### 单导入

根是**只含一个路径的数组**时，这个文件不是别名文件，而是指向另一个别名文件的指针：

```json title="~/.byk/alias/ops.byk.json"
["~/proj/web/run.byk.json"]
```

含义是「放弃自己的身份」：`@`/`@@` 前缀、key、默认优先级留在索引文件上，别名内容与一切声明都来自目标文件，相对路径也以**目标文件所在目录**为基准。所以同一份 bundle，直接扫描和通过索引导入，行为完全一致。

```json title="~/proj/web/run.byk.json"
{
  "$cwd": ".",
  "build": "node build.js",
  "deploy": "node deploy.js"
}
```

```bash
byk build           # 在 ~/proj/web 里执行 node build.js
byk @@ops.build     # 精确调用走索引的 key
```

| 规则 | 说明 |
|---|---|
| 只能一项 | 数组写多项时只用第一项，并在 stderr 提示 |
| 路径基准 | 相对**索引文件所在目录**解析，支持 `~` 和 `${...}` 变量 |
| 只允许一层 | 目标文件本身不能也是数组，否则报错并跳过该文件 |
| 身份 | key、`@`/`@@` 前缀、默认优先级来自索引；其余全部来自目标 |
| `$priority` | 照常生效：目标写 `-1` 会让索引一起退出合并命名空间，只剩精确调用 |

:::note
目标缺失、JSON 损坏、数组为空时，只跳过该文件，其他别名照常可用。
:::

### 优先级

所有参与合并的文件共享一个 key 空间，优先级高的覆盖低的。

#### 默认值

| 文件位置 | 默认优先级 |
|---------|-----------|
| 当前目录 `[name].byk.json` | 1 |
| 当前目录 `.byk.json` | 1（同级最后加载） |
| 全局 `[name].byk.json` | 0 |
| 全局 `.byk.json` | 0（同级最后加载） |

所以「就近优先」：项目里的文件自动覆盖全局同名别名，进目录就能 `byk <key>`，不用写任何声明。

同优先级文件按文件名字母序加载，匿名文件 `.byk.json` 排在同级最后，**后加载的覆盖先加载的**。所以同一目录里若 `a.byk.json` 与 `.byk.json` 都有 `build`，生效的是 `.byk.json` 那份。

:::note 在全局目录里运行
当 cwd 恰好是 `~/.byk/alias/` 时，那里的文件同时属于「当前目录」和「全局目录」。它会以两个身份被扫描（`@f` 与 `@@f` 都能精确调用），但**只按全局身份参与一次合并**，不会被合并两遍。
:::

#### 自定义

只想给本文件用、不想进公共空间，写 `-1`：

```json title="run.byk.json"
{
  "$priority": -1,
  "deploy": "deploy --env {env}"
}
```

这时 `byk deploy` 找不到它，只能 `byk @run.deploy`。

需要压过同目录的其他文件时，才需要写数字：

```json title="任意 .byk.json"
{
  "$priority": 20,
  "build": "vite build"
}
```

:::note
`$priority` 是保留字段，不会被当成别名 key。日常只需要记住两个取值：**不写（1 / 0，就近优先）** 和 **-1（只用精确语法）**。
:::

### 精确执行语法

| 语法 | 说明 |
|------|------|
| `byk @release.build` | 当前目录 `release.byk.json` 的 `build` |
| `byk @@release.build` | 全局 `~/.byk/alias/release.byk.json` 的 `build` |
| `byk @.build` | 当前目录匿名文件 `.byk.json` 的 `build` |
| `byk @@.build` | 全局匿名文件 `.byk.json` 的 `build` |

约定：

- 只做文件路由，不做 fallback
- 文件不存在 → `Alias file not found: @release`（全局报 `@@release`）
- 文件存在但 key 不存在 → `Alias key not found in file @release: build`
- 两种情况都以退出码 1 结束
