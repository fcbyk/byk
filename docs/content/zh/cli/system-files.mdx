# 系统文件

`@@@` 是第三个文件域。`@` 指向当前目录、`@@` 指向全局别名目录，`@@@` 指向 **CLI Home（`~/.byk/`）里的系统文件**——它们属于 byk 自己，不是任何项目的别名。

```bash
byk @@@文件 命令 [参数...]
```

目前只有 `@@@config` 一个：

| 写法 | 目标文件 |
|------|----------|
| `@@@config` | `~/.byk/config.json` |

- 系统文件不参与别名查找，也没有 `clone` / `link`：它们不存在“多份互链”的概念。
- `@@@` 后面的名字必须是注册过的系统文件，拼错会报 `Unknown system file` 并列出可用项。
- 动词与名字之间用空格，不是点号：`@@@config.set` 会报 `Invalid system file`。

## 命令

不带命令时打印全部设置（这也是最常用的一屏），`-h` 才是用法帮助。

| 命令 | 作用 |
|------|------|
| `list` | 列出全部设置项（等于不带命令） |
| `get <键>` | 打印一个值，可直接进 `$(...)` |
| `set <键> <值>` | 校验后写入 |
| `unset <键>` | 删除该键，回到默认值 |

```bash
byk @@@config                    # 看全部设置
byk @@@config get banner         # auto
byk @@@config set banner never   # 关掉帮助页顶部的装饰框
byk @@@config unset banner       # 回到默认
```

`get` 打印裸值；`set` / `unset` 的状态提示写 stderr，管道里不会混进输出。

## 设置项

| 键 | 取值 | 默认 | 作用 |
|----|------|------|------|
| `banner` | `auto` / `always` / `never` | `auto` | `-h` 顶部的装饰框 |

`auto` 在 stdout 不是终端时不显示——`byk -h | head`、脚本与编辑器插件拿到的帮助天然干净。`always` 与 `never` 是字面意思。

扫描别名文件时发现问题，那句 `N alias files have problems` **不受这个设置影响**：它是诊断，不是装饰。

## 文件

```json
{ "banner": "auto" }
```

- 文件不存在是正常状态，全部键用默认值，不报错。
- 内容读不懂（坏 JSON、顶层不是对象）时只打一行警告并全部回退到默认值，退出码照常——配置坏了不该连 `-h` 都打不开。
- 写入是原子的，并且保留读到的全部键，包括当前版本还不认识的键。
- 键按字母顺序写回，手写的顺序会被规范化。
- `byk --paths` 的 `Config:` 一行就是这个文件的位置。
