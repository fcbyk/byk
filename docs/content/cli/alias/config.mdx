# 别名配置

## 类型定义

```ts title="alias.types.ts"
// 别名对象类型
type AliasObject = {
  $cmd?: string;
  $cwd?: string;
  $interactive?: boolean;
  $description?: string;
  [key: string]: string | AliasObject | boolean | undefined;
}

// JSON 文件格式类型
type AliasFileJSON = {
  $priority?: number;      // 优先级，默认本地=10 全局=0
  $cwd?: string;           // 文件级 / 分组级工作目录，子别名自动继承
  $interactive?: boolean;   // 文件级 / 分组级交互模式，子别名自动继承
  $paths?: string[];        // 文件级 PATH 目录列表，子别名自动继承
  $var?: Record<string, string | Record<string, string>>;  // 文件级变量（阶段一替换）
  $assets?: AssetsBlock;    // 文件级资源下载声明
  [key: string]: string | AliasObject | number | boolean | undefined;
};
```

## 别名对象类型

### Key 命名规则

#### 普通字段

- key **不能包含** `@` 或 `.`，违规则被忽略
- 支持中文 key 名
- key 支持嵌套分组（dict），通过 `.` 分隔符访问

#### 前缀系统字段

通过 `$` 前缀系统字段配置别名：

| 字段 | 类型 | 说明 |
|------|------|------|
| `$cmd` | string | 执行命令（必填） |
| `$cwd` | string | 工作目录（可选，可继承） |
| `$interactive` | boolean | 是否交互执行（可选，可继承） |
| `$description` | string | 帮助页描述文本（可选，不可继承） |

:::note
`$cmd` 开头的 object 为别名叶子节点。仅有 `$cwd` / `$interactive` 而无 `$cmd` 的 object 为带继承属性的分组节点。`$priority` 为文件保留字段。
:::

### 工作目录 cwd

支持三级继承：文件级 → 分组级 → 别名级，优先级逐级递增（别名自己的 `$cwd` 覆盖分组级，分组级覆盖文件级）。

<Tabs>
<Tab label="别名级指定">

```json
{
  "install": {
    "$cmd": "npm i",
    "$cwd": "/project/web"
  }
}
```

</Tab>
<Tab label="分组级继承">

在中间分组上设置 `$cwd`，该分组下所有子别名自动继承，无需逐个指定。子分组可以覆盖：

```json
{
  "services": {
    "$cwd": "/project",
    "install": "npm i",
    "web": {
      "$cwd": "/project/web",
      "dev": "pnpm dev",
      "build": "pnpm build"
    }
  }
}
```

`install` 继承 `services` 的 `$cwd`（`/project`），`web.dev` 和 `web.build` 使用 `web` 分组覆盖的 `/project/web`。

</Tab>
<Tab label="文件级继承">

在文件顶层设置 `$cwd`，所有子别名未单独指定 `$cwd` 时会自动继承：

```json
{
  "$cwd": "/project/web",
  "install": "npm i",
  "start": {
    "$cmd": "pnpm dev",
    "$cwd": "/project/web/frontend"
  }
}
```

`install` 继承文件级 `$cwd`（`/project/web`），而 `start` 使用自行指定的 `/project/web/frontend`。

</Tab>
</Tabs>

### 交互模式

交互模式适合需要逐步确认参数或执行危险命令的场景。开启后逐项提示输入占位符值，最后确认执行。

`$interactive` 同样支持三级继承：文件级 → 分组级 → 别名级。

<Tabs>
<Tab label="别名级指定">

```json
{
  "deploy": {
    "$cmd": "deploy --env {env} --tag {version}",
    "$interactive": true
  }
}
```

```bash
byk deploy
# ~ deploy --env {env} --tag {version}
#   env: staging
#   version: v2.0
# ~ deploy --env staging --tag v2.0     ← 绿色粗体
#    Press Enter to execute...
```

</Tab>
<Tab label="分组级继承">

在中间分组上设置 `$interactive`，该分组下所有子别名自动启用交互模式。子节点可以覆盖为 `false`：

```json
{
  "danger": {
    "$interactive": true,
    "delete": "rm -rf {path}",
    "migrate": {
      "$cmd": "db migrate --env {env}",
      "$interactive": false
    }
  }
}
```

`delete` 继承 `danger` 的交互模式（确认后再执行），`migrate` 覆盖为非交互（直接执行）。

</Tab>
<Tab label="文件级继承">

在文件顶层设置 `$interactive`，所有子别名未单独指定时会自动继承：

```json
{
  "$interactive": true,
  "deploy": "deploy --env {env}",
  "build": {
    "$cmd": "pnpm build",
    "$interactive": false
  }
}
```

`deploy` 继承文件级交互模式，`build` 使用自行指定的非交互模式。

</Tab>
</Tabs>

:::tip
交互和非交互模式 header 和 final 行格式完全一致。交互只是多了 `~` 前缀的输入区和确认步骤。
:::

### 描述文本

`$description` 用于在帮助页中显示描述文本，替代默认的命令映射显示。适合命令本身不够直观的场景。

**不可继承** — 仅对当前别名生效，不会从文件级或分组级继承。

```json
{
  "更新版本号": {
    "$interactive": true,
    "$cmd": "cz bump {version}",
    "$description": "交互式更新版本号"
  }
}
```

帮助页显示效果：

```
Aliases:
  发布.更新版本号    交互式更新版本号
```

未设置 `$description` 时，帮助页默认显示命令映射：

```
Aliases:
  发布.更新版本号    cz bump {version}
```

### PATH 目录

`$paths` 用于在执行别名前将指定目录前置到 `PATH` 环境变量，使别名可以访问这些目录下的可执行文件。

**仅支持文件级设置**，所有子别名自动继承。

```json title=".byk.json"
{
  "$paths": ["./scripts", "~/tools/bin"],
  "deploy": "deploy.sh",
  "check": "lint.sh"
}
```

执行 `byk deploy` 时，`./scripts` 和 `~/tools/bin` 会被前置到 `PATH`，因此可以直接调用 `deploy.sh` 而无需指定完整路径。


:::note

- 相对路径以配置文件所在目录为基准解析
- 不存在的目录会被静默跳过
- `$paths` 仅在文件顶层设置，不支持别名级或分组级覆盖

:::

### 补全候选 $args

`$args` 为别名条目声明 shell 补全树，结构与插件协议的 `args` 字段完全一致：

```json title=".byk.json"
{
  "deploy": {
    "$cmd": "deploy --env {env}",
    "$args": {
      "$": ["prod", "staging"],
      "$options": ["--dry-run", "--verbose"],
      "build": {
        "$": ["debug", "release"]
      }
    }
  }
}
```

```bash
byk deploy <TAB>            # prod  staging  --dry-run  --verbose  build
byk deploy build <TAB>      # debug  release
byk deploy --dry-run <TAB>  # 已选过的选项被排除
```

| 特殊 key | 语义 |
|---------|------|
| `$` | 叶子候选数组，选中后无下级 |
| `$options` | 可重复选项数组，选中后留在当前层，已选过的自动排除 |
| 其他 key | 子命令，选中后进入其值继续补全 |

**规则**：

- `$args` 仅对当前条目生效，不继承
- 声明了 `$args` 的条目，补全走补全树（优先于点号子节点）；执行仍走 `$cmd`，互不影响
- `byk show <别名>` 的详情页会展示补全候选
- value 可以是 `string[]`（全部为叶子候选）或嵌套 object，支持任意层级

### 保留变量

别名命令中的以下变量由 byk 在执行前展开为具体路径，shell 不会看到 `$` 变量：

| 变量 | 展开为 | 说明 |
|------|--------|------|
| `$python` | byk 托管 venv 的 Python 解释器 | 与插件命令使用同一个解释器；venv 不存在时友好报错 |
| `$venv` | venv 的 bin 目录（Windows 为 `Scripts`） | 用于 `$paths` 或拼接路径 |
| `$byk` | byk 根目录 `~/.byk` | 引用插件产物等持久化数据 |
| `$assets` | 当前别名文件的资源下载根目录 | 引用 `$assets` 字段下载的产物；文件未声明 `$assets` 时明确报错 |

**规则**：

- 展开发生在占位符解析**之前**，`$cmd` / `$cwd` / `$paths` 三个位置一致生效
- 仅以上四个变量会被展开；其他 `$` 开头的内容（如 `$HOME`、`$PATH`）原样透传给 shell 处理
- 整词匹配：`$pythonfoo` 不会被误认为 `$python`
- 展开值包含空格时，byk 自动补上双引号，无需手写
- `${args}` 等系统占位符不受影响

```json title=".byk.json"
{
  "$paths": ["$venv"],
  "py": {
    "$cmd": "$python -m http.server {port}",
    "$interactive": true
  },
  "info": "$python -c \"import sys; print(sys.prefix)\""
}
```

```bash
byk py 8000        # 用 venv 的 python 启动 http.server
byk info           # 打印 venv 的 site-packages 前缀
```

### Python 依赖 $pip

文件级 `$pip` 声明该别名文件所需的 Python 依赖，经 `byk add pip` 安装到 byk 托管的 venv：

```json title=".byk.json"
{
  "$pip": ["rich", "click>=8.0"],
  "fmt": { "$cmd": "$python -m rich.markdown {file}" }
}
```

```bash
byk add pip @demo           # 安装当前目录 demo.byk.json 的 $pip
byk add pip @@demo          # 安装全局目录 ~/.byk/alias/demo.byk.json 的 $pip
byk add pip ./demo.byk.json # 直接传路径
```

| 规则 | 说明 |
|------|------|
| 取值 | `string \| string[]`，语法同 pip：包名、版本约束、`name @ url` |
| 作用域 | 仅文件级；子分组不需要也不继承 |
| 语义 | keep——不随文件删除自动卸载（venv 由 byk 托管，包可能被多个文件共享） |
| venv | 不存在时 `byk add pip` 按需创建（uv 优先，一次性确认） |
| 配合 | 别名命令用 `$python` 变量调用 venv 解释器（见上文保留变量） |

:::note
未声明 `$pip` 的文件执行 `byk add pip` 是友好的 no-op（退出码 0），不会触发 venv 创建。
:::

### 文件级变量 $var

`$var` 声明文件级变量，在**扫描阶段**（阶段一）做全局替换，作用于文件内所有字符串值——尤其适合长 URL 前缀、版本号等需要在多处复用的内容：

```json title=".byk.json"
{
  "$var": {
    "BASE": "https://github.com/owner/repo/releases/download/v1.2.0",
    "VER": "v1.2.0",
    "BIN": {
      "darwin-arm64": "$BASE/darwin-arm64",
      "linux-x86_64": "$BASE/linux-x64"
    }
  },
  "$assets": {
    "tool": "[exe] $BIN/tool"
  },
  "run": { "$cmd": "$assets/tool --version $VER" }
}
```

| 规则 | 说明 |
|------|------|
| 语法 | `$NAME`，约定全大写；替换发生在阶段一（扫描时，结果进缓存） |
| 作用域 | 文件级全局，`$cmd` / `$cwd` / `$paths` / `$assets` 等所有字符串值均生效 |
| 平台映射 | 值可为平台映射（当前平台取值）；值里可交叉引用其他变量 |
| 保留字 | 内置变量（`$python`/`$venv`/`$byk`/`$assets`）声明也无效，内置优先 |
| 未知变量 | 未定义的 `$xxx` 原样透传（阶段二由 shell 或内置变量处理） |

:::tip
两阶段展开：阶段一替换**用户变量**（`$NAME`），阶段二展开**内置变量**（`$python` 等）。因此用户变量可以组合内置变量——`{"TOOLS": "$byk/tools"}` 阶段一替换出 `$byk/tools` 字面量，阶段二再展开 `$byk`。
:::

### 资源下载 $assets

文件级 `$assets` 声明需要下载的资源，经 `byk add assets` 拉取。这是 byk.json 的 `downloads` 能力迁移后的形态——重新设计为「单一目标 + 声明式拉取」：

```json title=".byk.json"
{
  "$assets": {
    "$to": "$byk/tools/demo",
    "tool": "[exe] $BIN/tool",
    "helper": {
      "darwin-arm64": "[exe] $BASE/helper-mac",
      "linux-x86_64": "[exe] $BASE/helper-linux"
    },
    "toolchain": "[tar] $BASE/toolchain.tar.gz",
    "scripts/lint.sh": "$BASE/lint.sh"
  },
  "run": { "$cmd": "$assets/tool {args}" }
}
```

```bash
byk add assets @demo           # 拉取当前目录 demo.byk.json 的资源
byk add assets @@demo          # 拉取全局目录 ~/.byk/alias/demo.byk.json 的资源
byk add assets --cdn @demo     # GitHub raw 走 jsDelivr CDN 加速
```

| 规则 | 说明 |
|------|------|
| 目标 `$to` | 可选。变量/平台映射/`~`，相对路径相对文件目录解析，不存在自动创建。显式设置时条目直接落 `<root>/<名字>` |
| 缺省根 | 本地文件=文件所在目录，全局文件=当前工作目录；声明 1 条目平铺、≥2 条目自动进 `<root>/assets/` |
| 条目名 | 即资产相对路径，`/` 天然表达子目录；拒绝 `..`/绝对路径 |
| 源 | URL 或本地路径（相对文件目录）；条目值可为平台映射（当前平台不在映射 → 跳过） |
| 前缀 | `[exe]` 下载后加执行位；`[tar]` 解压到同名子目录；无前缀原样下载 |
| 幂等 | 每次全量重下，目标已存在则注记；不引入 `--force` |
| `$assets` 变量 | 展开为资源实际所在目录（吸收 root+容器逻辑），命令写 `$assets/...` 永远不用猜落点 |

:::note
未声明 `$assets` 的文件执行 `byk add assets` 是友好的 no-op（退出码 0），不会创建任何目录；命令里用了 `$assets` 变量但文件未声明则明确报错。
:::

### 安装标志 $install

`$install` 标记哪些别名需要被安装到全局（`byk add @file`）。它与 `$interactive` 完全同构——三级继承，opt-in（默认不装）：

```json title=".byk.json"
{
  "tools": {
    "$install": true,                       // 分组级：整组安装
    "lint": { "$cmd": "$python -m ruff {args}" },
    "fmt": "prettier --write {args}"
  },
  "dev": "vite dev",                        // 未标记 → 不安装，留在本地
  "one-off": { "$cmd": "echo hi", "$install": true }   // 别名级
}
```

```bash
byk add @demo          # 安装当前目录 demo.byk.json
byk add @demo --cdn    # 同时用 jsDelivr 加速 $assets 下载
```

| 规则 | 说明 |
|------|------|
| 作用域 | 文件级 / 分组级 / 别名级，子级 `false` 可覆盖，未指定继承上级 |
| opt-in | 默认不装；只有标记 `$install: true` 的别名子树进入全局副本 |
| 粒度 | 下载（`$pip`/`$assets`）是文件级的，筛选是别名级的——装整份依赖、只留标记别名 |
| 副本 | 安装后写 `~/.byk/alias/<file>.byk.json`（文件级字段 + 筛选后的别名，`$install` 本身不进入副本） |
| 无别名时 | 文件有 `$pip`/`$assets` 仍写副本（记录已安装内容，为卸载留钩子）；三者皆无 → 报错 |

:::note
`byk add @file` 只接受本地文件（`@`）；全局文件（`@@`）已在全局，没有「安装」语义。带 `$assets` 的别名若要装成全局工具，建议显式 `$to` 指向确定位置（如 `$byk/tools/xxx`），否则资源按缺省根规则落在运行时的当前目录。
:::

## 别名文件

byk 扫描当前目录和全局目录下所有 `*.byk.json` 文件，自动合并为一个统一的别名空间。

### 文件命名规范

| 格式 | 示例 | 说明 |
|------|------|------|
| `[name].byk.json` | `run.byk.json`, `release.byk.json` | 推荐形式，文件名有语义 |
| `.byk.json` | `.byk.json` | 极简形式，匿名文件 |

:::warning
**name 合法字符**：字母、数字、`-`、`_`、中文。

**禁止字符**：`.`、`@`、`/`、空格及其他特殊符号。

非法命名的文件（如 `aaa.bbb.byk.json`）会被**静默跳过**，不报错。
:::

### 目录结构

本地目录（当前工作目录，不递归扫描子目录）：

```tree
./
├── run.byk.json
├── release.byk.json
└── .byk.json
```

全局目录：

```tree
~/.byk/alias/
├── alias.byk.json
├── work.byk.json
└── .byk.json
```

### 优先级

所有文件合并为一个统一的 key 空间，高优先级文件的同名 key 覆盖低优先级。

#### 默认优先级

| 文件位置 | 默认优先级 |
|---------|-----------|
| 本地 `[name].byk.json` | 10 |
| 本地 `.byk.json` | 10（匿名文件排序靠后） |
| 全局 `[name].byk.json` | 0 |
| 全局 `.byk.json` | 0（匿名文件排序靠后） |

同优先级文件按文件名字母序加载，后者覆盖前者，行为确定。

#### 自定义优先级

通过 `$priority` 字段声明，可打破默认规则：

```json title="任意 .byk.json"
{
  "$priority": 20,
  "build": "vite build",
  "dev": "vite"
}
```

:::note
`$priority` 为保留字段，不会被解析为别名 key。设为负数（如 `-1`）的文件不参与优先级合并，仅可通过精确语法调用。
:::

### 精确执行语法

日常使用直接 `byk <key>`。当需要精确指定执行哪个文件中的别名时：

| 语法 | 说明 |
|------|------|
| `byk @release.build` | 精确执行本地 `release.byk.json` 的 `build` |
| `byk @@release.build` | 精确执行全局 `release.byk.json` 的 `build` |
| `byk @.build` | 精确执行本地 `.byk.json` 的 `build` |
| `byk @@.build` | 精确执行全局 `.byk.json` 的 `build` |

**约定**：
- `@` 语法只做文件路由，不做任何 fallback
- 文件不存在 → 报错，不自动查找其他位置
- 文件存在但 key 不存在 → 报错
- Key 名不能包含 `@`，违反则静默跳过

```bash title="精确执行示例"
# 本地文件不存在
byk @release.build
# Error: local file "release.byk.json" not found

# 全局文件不存在
byk @@work.deploy
# Error: global file "work.byk.json" not found

# key 不存在
byk @release.cleanup
# Error: alias "cleanup" not found in release.byk.json
```
